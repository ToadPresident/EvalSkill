# Demonstrating EvalSkill

The demonstrable promise is: **install a portable skill, provide a benchmark name, and get a complete analysis whose reasoning can be traced to evidence**. Avoid equating one-command installation with a proven improvement in scientific judgment.

## Short walkthrough

1. In an empty project, run the pinned installation command from [the installation guide](INSTALLATION.md), selecting your coding agent.
2. Show that `scientific-benchmark-validity` is discoverable in the host. Open its entrypoint to show the same English package is reused.
3. Give a short request: `Use scientific-benchmark-validity to help me understand CORE-Bench. Produce one complete English M2M report.` A local primary-source packet makes a live demonstration less dependent on network retrieval; disclose that it was supplied.
4. Inspect the result in this order: task and scoring conditions; one precisely attributed claim; its supporting evidence and missing relationship; the supported narrower conclusion. The entire five-dimensional report remains available.
5. Optionally ask how the interpretation changes for a different use. The analysis should follow that use rather than repeat a fixed verdict.

For a short talk, prepare the completed report before the presentation and label it as a prior run. A live installation/discovery segment can show portability without pretending a long analysis completes instantly. Reuse a frozen version and retain the first completed output.

## What to point out

| Feature | Observable demonstration |
|---|---|
| Low input burden | A name or paper starts the workflow; no user-authored measurement profile required. |
| Portable package | The same folder installs for multiple hosts; no mandatory provider-specific MCP or service. |
| Complete argument | Evidence, inference, gap/satisfaction, judgment basis and revision condition for each material claim/dimension. |
| Conditional computation | Existing response data enable diagnostics; absent data do not produce invented analyses. |
| Traceability | Follow a decisive observation to its exact source; distinguish file integrity from scientific support. |

## Claims to keep separate

- **Installation:** the package reaches the documented directories with its files intact.
- **Activation:** the host discovers and loads the intended skill.
- **Execution:** the host completes the requested workflow.
- **Quality and understanding:** the output is better, or researchers interpret benchmarks more accurately.

The first three enable the fourth; they do not establish it. [VALIDATION.md](../VALIDATION.md) identifies the evidence currently available. The planned interactive companion and controlled user study are described in [development priorities](DEVELOPMENT.md), not advertised as implemented features.
