# Pre-delivery review

This is our I08 procedure. Perform it within the same request before delivering the report. It is a source-grounded self-review unless a separate reviewer actually participates. Read the relevant source passages; matching headings or completing a checklist is not verification.

## Checks that can change the report

| Target | Review action |
|---|---|
| Facts | Recheck decision-relevant numerical and protocol clauses using the evidence worksheet. Verify qualifiers independently, including resources, time conditions, uncertainty labels, and whether a value is measured or adjusted. Correct or qualify unsupported wording. |
| Outcome completeness | For each decisive study, inspect available outcome tables. Separate completion, target matching and independent correctness validation; do not call an outcome unmeasured merely because it lacks independent validation. |
| Delivery consistency | Preserve route/version/use qualifiers in compact judgments. Scan the actual report when checking evidence IDs. Keep systems/items with no graded responses visible as undefined scores, and state whether task coverage uses an expected inventory or only observed rows. |
| Data and execution | Check version/condition identity, task hierarchy, valid scale, missingness and repeat structure against the profile. Inspect command status and actual outputs. Preserve author results, this run's computation, failures and demonstrations separately. |
| Analytical relevance | Identify each operation's claim/use relationship. Confirm eligibility and uncertainty scope. Do not treat software success as scientific support. |
| Verification meaning | Separate integrity, facts, relevance and execution. Matching hashes/excerpts cannot certify inference; zero extracted quotes do not establish absence. |
| Claims and routes | Preserve owner, target, population, format, and context. Keep fixed observations separate from class claims; do not add a construct requirement to a route that does not need it. Separate achievement thresholds from validity. |
| Every dimension | Locate actual evidence, warrant/application condition, material gap or satisfaction condition, decisive rating reason, and revision condition. A source citation or filled table does not replace any of these. A concise operational-satisfaction branch is valid. |
| Rating basis | Apply judgment-and-use.md. Does the explanation identify why this label fits better than a plausible neighboring label? Is a missing study being treated mechanically as failure? Does a changed rating have an aligned claim/use and an attributable reason? |
| Consequences | Trace the actual interpretation, behavior/decision, population/setting, and outcome from the U record through evidence, rationale, label, conclusion, and proposed study. Detect semantic substitution even if the ID stayed unchanged. Separate anticipated effects from observed impacts. |
| Alternatives and source roles | Distinguish untested alternatives from demonstrated mechanisms, duplicated reports from replications, and framework rules from empirical evidence. Check whether the evidence can actually distinguish the intended interpretation. |
| Completeness and compression | Remove repeated facts, generic caveats, copied rule explanations, and repeated study proposals. Keep every claim-specific inferential step, source locator, and revision condition. Do not conceal missing analysis in an appendix. |

When useful, correct a disputed fact or change one claim condition and inspect which conclusion should change. These are reasoning checks, not new experiments.

## Review record and stopping point

Record only actual material findings: location, source/rule, correction or unresolved issue, and effect on the argument. If no issue was found, state the inspected scope without claiming the report is error-free. Identify the generating assistant, fresh model reviewer, or human accurately. Repair material issues and recheck affected arguments; do not launch an indefinite loop.

For calibration, the first completed report may include the runner's ordinary self-review and revisions before delivery. Freeze it when the runner reports completion. Subsequent outside review must leave that raw artifact unchanged; save findings or a separately labelled corrected edition instead. This prevents post-run repairs from being credited to one-request generation.

Compare aligned evidence access, claims, uses, and task instructions. Separate design additions, observed output changes, source-supported improvements, and general effectiveness not yet tested. Check that a supposed improvement was actually absent from the baseline. A stricter rating, matching the source, or shorter length alone is not an improvement. Measure length including the evidence index, and confirm that compression retained the analysis; sidecar removal is not a substantive saving if it hides required reasoning.
